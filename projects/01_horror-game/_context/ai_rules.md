# AI作業ルール定義

## 基本方針
- コード生成・実装提案はすべて `project_overview.md` と `environment.md` の前提に沿って行う
- 作業開始時は必ず `INDEX.md` を参照し、対象タスクに必要な最小限のフォルダのみ読み込む

## 作業進行ルール
- **作業は「やってください」等の明示的な実行指示が出てから開始する**
- 提案・相談フェーズでは実装・ファイル生成を行わない
- 承認確認は原則不要。作業完了後にまとめて報告する
- 以下の高重要度アクションのみ事前確認を行う:
  - 既存ファイルの削除・上書き（内容が大きく変わる場合）
  - APIキー・シークレット情報の変更
  - Git の強制プッシュ（force push）や履歴の書き換え
  - プロジェクト構成の大幅な変更（フォルダ構成の再編等）

## フォルダ読み込みルール（タスク別）

| 作業内容                         | 読み込むフォルダ                          |
|----------------------------------|-------------------------------------------|
| 新規コード生成・実装相談         | `_context/` + `godot/該当シーン or スクリプト` |
| バグ修正・既存コード改修         | `_context/` + 該当ファイルのみ            |
| アセット・素材整理               | `_context/` + `assets/`                   |
| ストーリー・シナリオ作業         | `_context/` + `story/`                    |
| 設計・仕様検討                   | `_context/` のみ                          |

## コード生成ルール
- 言語: GDScript（Godot Engine 準拠）
- 軽量・タブレット動作を意識し、重い処理は避ける
- コメントは日本語で記述する
- シーン構成・ノード名は英語スネークケースで統一する

## NG事項
- 前提と無関係なエンジン（Unity / Unreal 等）のコードを提案しない
- 重量級ライブラリ・プラグインを無断で追加しない
